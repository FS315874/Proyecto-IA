# v0.19 — Proyectos y documentos aprobados

## Alcance

Esta versión agrega una sola capacidad: abrir en Visual Studio Code carpetas de
proyecto y documentación de texto elegidas explícitamente por el usuario. No busca
archivos por todo el disco, no abre ejecutables ni controla el interior de VS Code.
Las órdenes de voz conservan la transcripción revisable existente; no se agregó
captura permanente ni un modelo nuevo.

## Uso y recorrido

1. En la GUI, abrir **Mis proyectos**, escribir un nombre identificable y seleccionar
   una carpeta con **Agregar proyecto** o un archivo de texto con **Agregar documento**.
   Para documentación se admiten `.md`, `.markdown`, `.txt` y `.rst`.
2. Pedir «abrí el proyecto Proyecto IA» o «abrí la documentación de Guía IA», usando
   los nombres efectivamente registrados. El catálogo se puede listar sin rutas con
   `python -m desktop_agent --targets`.
3. Para revocar un destino, seleccionarlo y elegir **Quitar seleccionado**. Esto
   quita la autorización local; no elimina el proyecto o archivo.

El parser resuelve frases conocidas sin IA. Si la IA está habilitada, sólo puede
proponer `OPEN_APPROVED_TARGET` con un nombre, nunca una ruta. Tanto la acción simple
como los planes pasan por `ActionExecutor` y por la herramienta registrada. La
herramienta vuelve a consultar el catálogo y comprueba existencia, tipo y ruta antes
de iniciar VS Code. El parser conserva si el usuario pidió un proyecto o un
documento, por lo que «proyecto IA» no compite con «documentación de Guía IA». Un
nombre abreviado sólo se acepta si tiene al menos dos caracteres y coincide de forma
única dentro del tipo pedido; ante ambigüedad se pide el nombre completo.

## Seguridad y privacidad

El catálogo tiene como máximo 50 destinos y se guarda de forma atómica fuera del
repositorio, en `%LOCALAPPDATA%\DesktopAgent\approved_targets.json`. Contiene nombres,
tipos y rutas locales; no se guarda en la configuración de claves ni se envía al
proveedor de IA. No debe subirse a Git. Un catálogo ilegible, una ruta desaparecida
o un destino que cambió desde la aprobación hacen fallar la apertura. No se abren
rutas UNC ni documentos ejecutables.

La apertura usa un ejecutable `.exe` de VS Code del catálogo fijo, sin shell, con la
ruta aprobada como argumento literal. Un `code.cmd` encontrado en PATH no se usa.
Los mensajes de resultados y el listado CLI no incluyen rutas. Los eventos del
ejecutor siguen registrando intención, herramienta, resultado y duración sin
copiar la ruta ni el contenido del documento.

El mantenimiento del 2026-09-19 agregó diagnósticos cerrados para catálogo vacío,
nombre ambiguo, ruta no disponible, ruta cambiada y catálogo inválido. Así, el
historial conserva `open_approved_target` y la etapa segura del fallo en vez de
degradarlos a `tool_failed`, sin guardar nombres, rutas ni contenido.

## Verificación y límites

Las pruebas automatizadas usan un catálogo temporal, lanzador y observador de
procesos ficticios: cubren persistencia, ambigüedad, corrupción, extensión no
permitida, ruta eliminada, rechazo de lanzador de shell, parser, propuestas de IA,
planes, ejecutor y GUI. El runner específico es
`python -m scripts.targets19_qa_check`; la suite completa es
`python -m unittest discover -s tests -v`.
Al cierre de la implementación pasaron **99 pruebas específicas, 539 Python y 13
JavaScript**; el runner específico selecciona un subconjunto de la suite completa.

La herramienta confirma que se solicitó la apertura y que el proceso `Code.exe` está
activo. **No demuestra** que VS Code cargó el proyecto/documento en la ventana
correcta; el resultado lo declara expresamente. Si Code.exe ya estaba activo,
comprobar sólo el proceso no distingue la ventana anterior de la nueva. El usuario
aprobó el recorrido visible con su proyecto y documentación el 2026-09-19. No se
hizo una apertura real como parte de la suite ni se usó la API de OpenAI.

`POLISH-08` de v0.17 permanece independiente y pendiente: voz/atajo reales y
YouTube audible con la extensión recargada. La aprobación de v0.19 proviene de la
prueba personal, no de las pruebas simuladas. Volumen por dispositivo avanzó luego
como v0.20; respuestas habladas y acceso móvil siguen siendo decisiones posteriores.

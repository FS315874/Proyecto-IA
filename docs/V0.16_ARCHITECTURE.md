# Decisión de arquitectura de v0.16

## 1. Objetivo

v0.16 amplía el lanzador local para abrir aplicaciones y juegos de uso habitual con
órdenes de texto o voz. La capacidad se limita a iniciar un destino permitido y
comprobar que su proceso apareció. No controla todavía la interfaz interna de esas
aplicaciones.

Los destinos incorporados son:

- Steam;
- VoiceMeeter Banana;
- League of Legends;
- God of War Ragnarök.

Spotify ya pertenecía al catálogo de v0.15. Reproducir una playlist dentro de Spotify,
buscar archivos o proyectos y cambiar el volumen de Windows quedan fuera de esta
versión porque requieren herramientas y verificaciones distintas.

## 2. Contrato de seguridad

La frontera existente se conserva:

```text
texto revisado
  -> parser determinista o propuesta estructurada de Luna
  -> identificador canónico del catálogo
  -> Action OPEN_APPLICATION validada localmente
  -> ActionExecutor
  -> open_application
  -> ruta o nombre fijo del catálogo
  -> subprocess.Popen([executable]) sin shell
  -> verificación local del proceso
```

El usuario y el modelo no pueden proporcionar una ruta, un ejecutable, argumentos,
un comando de shell, un nivel de riesgo ni una herramienta. Una propuesta externa es
un dato no confiable y sólo puede seleccionar una clave ya presente en
`SUPPORTED_APPLICATIONS`. El núcleo vuelve a construir la acción con política local.

Abrir una aplicación continúa clasificado como `SAFE`: es un efecto local visible,
reversible y ya permitido por el contrato de v0.2. v0.16 no concede escritura de
archivos, interacción con cuentas, compra, envío ni control libre de mouse o teclado.

## 3. Interpretación rápida y natural

Los alias frecuentes usan el parser determinista y no consumen API. Entre otros:

```text
abrí Steam
abrí VoiceMeeter Banana
abrí League of Legends
abrí God of War Ragnarok
```

Una formulación diferente puede usar el fallback existente de `gpt-5.6-luna` sólo
cuando la IA está habilitada. El lanzador `python -m scripts.start_voice_gui` habilita
voz e interpretación natural para la misma ejecución efímera. La API key no se guarda
y todas las llamadas de texto, voz y visión comparten el libro mensual y el límite de
USD 1,00 por defecto.

El modelo se usa porque puede clasificar formulaciones variables, no para ejecutar la
computadora. OpenAI documenta que GPT-5.6 Luna admite Responses y salidas estructuradas;
el adaptador conserva `reasoning.effort=none`, esquema JSON estricto, `store=false`,
timeout y cero reintentos automáticos. Referencia consultada el 2026-08-26:
[GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna).

## 4. Resolución local

Cada entrada del catálogo declara por separado:

- nombre visible;
- nombres de ejecutable aceptados para búsqueda en `PATH`;
- rutas de instalación conocidas;
- nombres de proceso válidos para verificación.

La resolución prueba primero las rutas fijas expandidas desde variables conocidas de
Windows y luego `shutil.which` con nombres fijos. No recorre el disco, no ejecuta una
búsqueda producida por IA y no interpreta comodines.

Las rutas actuales cubren las instalaciones comprobadas en el equipo y ubicaciones
habituales de Steam. Una instalación personalizada no se descubre automáticamente:
falla con un mensaje controlado y debe agregarse explícitamente al catálogo después de
verificarla.

## 5. Verificación observable

Que `Popen` no arroje una excepción sólo prueba que Windows aceptó la solicitud. v0.16
agrega una comprobación posterior acotada:

1. obtiene un snapshot local con `CreateToolhelp32Snapshot`;
2. recorre nombres mediante `Process32FirstW` y `Process32NextW`;
3. compara únicamente contra nombres de proceso del catálogo, sin coincidencia parcial;
4. reintenta como máximo veinte veces cada 250 ms;
5. declara éxito sólo si observa uno de los procesos esperados.

La lista de procesos existe sólo en memoria y no se registra ni se envía a servicios.
Si la enumeración nativa falla, la comprobación vence o el resultado es ambiguo, la
herramienta declara fallo seguro. No intenta cerrar el proceso porque podría haber
arrancado tarde y una terminación automática sería un efecto nuevo y más riesgoso.

Esta evidencia confirma proceso activo, no ventana lista, sesión iniciada, audio
correcto ni estado interno de un juego.

## 6. Validación

Las pruebas automatizadas sustituyen rutas, inicio, espera y observación de procesos.
Cubren:

- los cuatro destinos nuevos y sus alias;
- rechazo de una aplicación fuera del catálogo;
- resolución por ruta fija y por `PATH`;
- error de inicio redactado;
- reintento y éxito observable;
- fallo seguro sin evidencia;
- enumeración nativa y coincidencia exacta de procesos;
- exposición de las nuevas claves al esquema estructurado de Luna;
- activación conjunta de voz e interpretación natural en el lanzador efímero.

`python -m scripts.application16_qa_check` recorre los cuatro comandos y un rechazo
con dobles. No abre aplicaciones, no usa micrófono, no llama a OpenAI y no consume
presupuesto.

## 7. Límites y prueba manual

- No se introducen argumentos de línea de comandos o URIs de lanzamiento.
- No se busca ni abre un proyecto o archivo por nombre.
- No se controla Spotify, Steam, Riot Client, un juego ni VoiceMeeter después de abrir.
- No se modifica volumen, salida de audio o configuración de Windows.
- Una ruta personalizada requiere una entrada revisada en el catálogo.
- El fallback natural requiere red, una API key con facturación y presupuesto local.
- La validación visible de los cuatro programas debe hacerla el usuario para evitar
  iniciar juegos o clientes reales durante la suite automática.

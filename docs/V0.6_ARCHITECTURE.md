# Decisión de arquitectura de v0.6

## Alcance

v0.6 observa una región de una ventana local concreta. No interpreta la imagen, no
elige acciones y no captura el escritorio completo por defecto. Los frames no salen
del proceso ni se guardan durante el flujo normal.

## Contratos

- `WindowTarget`: identificador opaco, handle, proceso, tamaño cliente y revisión.
- `CaptureRegion`: rectángulo relativo al área cliente de la ventana.
- `RasterFrame`: bytes BGRA32 inmutables y dimensiones comprobadas.
- `Observation`: referencia temporal sin incorporar los píxeles a logs o resultados.
- `CaptureBackend`: puerto reemplazable para pruebas y otros mecanismos futuros.

## Límites y vigencia

Los valores predeterminados permiten como máximo 1280 × 720 píxeles, ocho capturas,
una captura por ventana cada 250 ms y treinta segundos de retención. La región debe
estar completamente dentro de la ventana. El servicio falla de forma segura si el
backend cambia dimensiones o devuelve un formato inesperado.

Cada observación queda ligada a `window_id` y `revision`. Un cambio de estado elimina
los frames de esa ventana, incrementa la revisión y vuelve obsoleta la referencia
anterior. El cierre elimina todo lo retenido.

## Privacidad

Las áreas sensibles se declaran en coordenadas relativas a la captura y se vuelven
negras antes de exponer el frame. Los logs solo contienen identificadores opacos,
revisión, dimensiones, cantidad de redacciones, estado y duración implícita; no
registran título, píxeles ni contenido visible.

## Backend de Windows

Se eligieron APIs nativas mediante `ctypes` para no introducir una dependencia solo
por esta capacidad. El backend descubre una única ventana por título exacto y guarda
internamente los objetivos emitidos. Antes de capturar verifica existencia,
visibilidad, estado no minimizado, proceso y tamaño. GDI copia únicamente la región
solicitada del área cliente.

## Validación realizada

- once pruebas con frames sintéticos para contratos, límites y redacción;
- frecuencia, cantidad, vencimiento, cierre e invalidación;
- aislamiento por ventana y errores redactados;
- importación y compilación del backend nativo;
- demo real autorizada sobre una ventana propia con datos ficticios;
- imagen mantenida solo en memoria y descartada al cerrar;
- suite completa de 183 pruebas.

## Limitaciones

- el backend nativo actual es exclusivo de Windows;
- una ventana cubierta puede producir píxeles diferentes según el compositor;
- las regiones sensibles deben conocerse antes de exponer el frame;
- todavía no existe interpretación visual ni una acción que consuma coordenadas.

# Decisión de arquitectura de v0.5

## Alcance

v0.5 permite representar y ejecutar una tarea de varios pasos usando solamente las
acciones que ya conoce Desktop Agent. No incorpora bucles libres, reintentos
autónomos, nuevas herramientas, memoria procedural ni control visual.

## Contrato

`TaskPlan` contiene un identificador local y entre dos y cinco `PlanStep`. Cada paso
contiene una `Action` existente y produce un `PlanStepResult`. El plan termina con un
estado explícito: éxito, fallo, cancelación, timeout o rechazo.

Los límites predeterminados son cinco pasos y treinta segundos. Se comprueban antes
de ejecutar y entre pasos. La cancelación es cooperativa: nunca mata una herramienta
a mitad de una operación bloqueante.

## Interpretación

`TaskPlanner` conserva el camino determinista como primera opción. Separa únicamente
marcadores explícitos (`;`, `luego`, `y después`) y exige que cada fragmento sea una
orden ya admitida por el parser.

El proveedor opcional usa Responses con `store=False`, un máximo de 512 tokens de
salida y un JSON Schema estricto. La respuesta externa solo puede incluir una versión
de esquema y pasos con `intent` y `target`. Se comparte la configuración, el timeout,
el modelo y el presupuesto mensual ya existentes. Las pruebas usan un cliente falso;
no se hizo una llamada real ni se usó una credencial.

## Validación y ejecución

La propuesta del modelo es dato no confiable. Cada paso se reconstruye desde los
catálogos locales. Antes del primer efecto se valida el plan completo:

- cantidad e identificadores únicos;
- coherencia entre intención, herramienta y argumentos;
- destinos y consultas permitidos;
- `RiskLevel.SAFE` y ausencia de confirmación pendiente;
- registro efectivo de cada herramienta en `ActionExecutor`.

`TaskPlanExecutor` ejecuta en orden y nunca reintenta por sí mismo. Un fallo detiene
la secuencia y marca el resto como omitido. La cancelación y el timeout se observan
entre pasos. Los logs omiten órdenes y argumentos.

## Validación realizada

- planes deterministas y propuestas externas simuladas;
- rechazo previo a efectos de un paso inválido o un plan demasiado largo;
- ejecución ordenada, fallo intermedio, cancelación y timeout;
- observabilidad sin contenido privado;
- solicitud estricta simulada al SDK;
- demostración local de dos pasos web;
- suite completa de 172 pruebas y compilación del paquete.

## Limitaciones

- la UI de v0.4.1 todavía envía órdenes individuales;
- no se cancela una herramienta mientras está bloqueada;
- el proveedor externo permanece opt-in y no fue probado con una llamada real;
- los planes no contienen condiciones, ramas ni reintentos.

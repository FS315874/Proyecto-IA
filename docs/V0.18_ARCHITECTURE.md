# v0.18 — Control oficial de Spotify

## Objetivo y alcance autorizado

El usuario autorizó el 2026-09-14 incorporar control de Spotify a Desktop Agent.
La capacidad principal de esta versión es transformar pedidos naturales en operaciones
explícitas de Spotify, ejecutarlas mediante la Web API oficial y comprobar su estado
final. No inspecciona ni manipula la interfaz del cliente; únicamente delega una URI
codificada para mostrar búsquedas. No lee bibliotecas ajenas, no publica contenido y
no amplía el control de otras aplicaciones.

## Qué se implementó

- OAuth 2.0 Authorization Code con PKCE, apropiado para una aplicación de escritorio
  que no puede guardar un client secret con seguridad.
- callback local fijo `http://127.0.0.1:43817/callback`, con `state`, code verifier,
  timeout y respuesta local sin tokens;
- access token sólo en memoria y refresh token cifrado para el usuario de Windows
  mediante el protector DPAPI existente;
- migración compatible del archivo de configuración de esquema 1 a esquema 2;
- búsqueda de canciones, resolución de playlists propias, reproducción, pausa,
  reanudación, siguiente, anterior y volumen;
- selección de un dispositivo configurado o de una única computadora disponible;
  nunca se elige un teléfono como fallback ni se adivina entre varias computadoras;
- comprobación posterior de `is_playing`, canción/contexto, dispositivo o volumen,
  según la operación;
- intents distintos para búsqueda y controles, tanto en el parser determinista como
  en propuestas simples y planes de IA;
- diagnósticos cerrados de configuración, autorización, red, permisos, dispositivo,
  contenido, rate limit y estado final no confirmado.

## Recorrido de ejecución

```text
Texto o voz revisada
  -> parser determinista o propuesta IA estructurada
  -> Action(intent=MEDIA_PLAYBACK, tool_name y argumentos cerrados)
  -> ActionExecutor
  -> SpotifyPlaybackTool
  -> SpotifyTokenSession
       ├── refresh token cifrado disponible -> renovar access token
       └── primera vez -> navegador -> consentimiento PKCE -> callback local
  -> SpotifyWebApi
  -> leer estado final y verificar
  -> ToolResult o fallo estructurado
```

La IA no construye URLs, scopes, device IDs, cuerpos HTTP ni credenciales. Sólo puede
proponer uno de los intents permitidos y datos acotados como canción, playlist o un
porcentaje canónico. El núcleo vuelve a validar y el ejecutor decide la herramienta.

## Configuración y autorización

1. Crear una aplicación personal en el
   [Spotify Developer Dashboard](https://developer.spotify.com/dashboard).
2. Registrar exactamente `http://127.0.0.1:43817/callback` como Redirect URI.
3. Si se autorizará una cuenta distinta a la propietaria, agregarla en
   **Settings → Users Management** de la aplicación.
4. En **Configuración** de Desktop Agent, activar Spotify y pegar únicamente el
   Client ID. No se solicita ni se guarda el client secret.
5. Opcionalmente escribir el nombre exacto del dispositivo Spotify de esta PC.
6. Guardar. La primera orden de reproducción abre el consentimiento de Spotify.

Los scopes solicitados son `user-modify-playback-state`,
`user-read-playback-state`, `playlist-read-private` y
`playlist-read-collaborative`. Se necesitan para controlar el reproductor, verificar
su estado y resolver playlists de la biblioteca. Spotify exige actualmente Premium
para el propietario de una aplicación en Development Mode, y limita esas aplicaciones
a una allowlist de usuarios. La autorización puede revocarse desde Spotify y el token
local puede quitarse marcando **Desconectar** en Configuración.

## Comandos comprobados por contrato

```text
Poné la canción As It Was en Spotify
Poné mi playlist 7W7 en Spotify
Buscá la canción As It Was en Spotify
Pausá Spotify
Seguí reproduciendo Spotify
Siguiente canción en Spotify
Volvé a la canción anterior en Spotify
Poné el volumen de Spotify al 35 %
```

`buscá` abre la búsqueda visible sin reproducirla y además informa el primer resultado
del catálogo. Usa un URI `spotify:search:` codificado y, si Windows no tiene ese
protocolo disponible, Spotify Web. `poné` reproduce el resultado. Las variantes libres
pueden usar el proveedor de IA si está habilitado, pero terminan en las mismas acciones
locales. Los nombres se tratan como datos y no aparecen en logs de diagnóstico.

## Decisiones y fallos seguros

- API oficial antes que DOM, visión, mouse o teclado: reduce latencia y dependencia de
  la interfaz visible de Spotify.
- La primera canción del buscador de Spotify se usa sólo cuando el usuario pidió
  reproducir; una playlist requiere coincidencia normalizada única en la biblioteca.
- `7 W7` y `7W7` coinciden, pero dos playlists equivalentes producen ambigüedad.
- Para iniciar contenido se elige el dispositivo configurado o una única computadora.
  Si hay varias, se exige configurar el nombre. Un teléfono activo no se usa como
  fallback oculto.
- `200`, `202` o `204` sólo indican que el comando fue recibido. Su cuerpo se descarta
  porque la API real puede devolver texto no JSON; la herramienta vuelve a leer el
  reproductor antes de informar reproducción, pausa o volumen confirmado.
- Siguiente/anterior comparan la URI y la posición antes/después. Si no cambia la
  pista ni hay un reinicio claro de posición, fallan como `spotify_not_confirmed`.
- No hay reintentos automáticos ante rate limit o fallos de servicio. Sólo un `401`
  produce una renovación y un único reintento de la misma solicitud.
- Las respuestas y excepciones externas se reducen a mensajes locales; tokens,
  consultas, cuerpos HTTP y nombres de dispositivos no se registran.

## Validación automatizada

`python -m scripts.spotify18_qa_check` cubre, sin red externa ni efectos reales:

- configuración inválida y migración del esquema anterior;
- cifrado, eliminación y no exposición del refresh token;
- autorización inicial, renovación y cache de access token mediante dobles;
- reintento único tras `401`;
- validación estricta de dispositivos, búsqueda y estado de reproducción;
- canción, playlist, pausa, reanudación, siguiente, anterior y volumen;
- rechazo de teléfono, computadora ambigua, contenido ambiguo y valores inválidos;
- parser, proveedor de IA, planes, ejecutor y diagnósticos.

Resultado del cierre: **127 pruebas** en el runner específico, **524 pruebas Python**
en la suite completa —incluidos los recorridos Tk— y **13 pruebas JavaScript** de la
extensión, todas aprobadas. La suite completa necesitó acceso a la instalación local
de Tcl/Tk fuera del sandbox. El test OAuth automatizado usa únicamente loopback local;
las pruebas automatizadas no realizan autorización, red externa ni reproducción real.

## Aceptación personal completada: SPOTIFY-18-08

El 2026-09-16 se completó el recorrido real, combinando las comprobaciones previas del
usuario con una repetición controlada después de la corrección:

1. el usuario configuró PKCE y confirmó reproducción y audio en su computadora;
2. se cerró Desktop Agent y una nueva ejecución reprodujo `7w7` sin nuevo login,
   comprobando persistencia del refresh token protegido;
3. pausa, reanudación, siguiente, anterior y volumen al 35 % quedaron confirmados por
   lectura posterior del reproductor;
4. una búsqueda visible fue aceptada por el protocolo de Spotify e informó el primer
   resultado sin iniciar reproducción;
5. una canción aislada recibió otra pista de Spotify con título visible equivalente,
   por lo que el caso real «sin siguiente» no pudo forzarse. La regresión exige cambio
   de URI o reinicio claro de posición y falla si el estado permanece igual.

La primera pausa de este recorrido descubrió que Spotify podía ejecutar la orden con
un estado exitoso y un cuerpo no JSON. El cliente lo interpretaba como fallo después
del efecto. Se corrigió descartando el cuerpo únicamente para comandos del reproductor
y manteniendo la lectura posterior como evidencia; la repetición real aprobó.

## Limitaciones

- Requiere una aplicación Spotify Developer propia, cuenta Premium, conexión y al
  menos un cliente Spotify disponible.
- La búsqueda de canción adopta la relevancia del buscador oficial; para reducir
  ambigüedad conviene incluir artista.
- La API puede no exponer o permitir volumen en ciertos dispositivos.
- La autorización interactiva espera como máximo 180 segundos. La GUI continúa
  respondiendo, pero una llamada HTTP ya iniciada no ofrece cancelación instantánea.
- Los límites y reglas de Development Mode pertenecen a Spotify y pueden cambiar.
- La apertura de una búsqueda sólo confirma que Windows aceptó el protocolo o su
  fallback web; el contenido visible exacto requiere observación humana.
- La suite simulada por sí sola no demuestra audio audible, dispositivo físico
  correcto ni consentimiento real; esas propiedades se registraron por separado en
  la aceptación personal.

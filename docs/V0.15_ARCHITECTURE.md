# Decisión de arquitectura de v0.15

## 1. Problema observado

La automatización de YouTube de v0.4 usaba un Chromium aislado de Playwright. Era una
decisión segura y reproducible, pero no reutilizaba la sesión habitual: podía abrir
un navegador visualmente distinto, demoraba el arranque de un proceso nuevo y cerrar
la herramienta cerraba ese navegador. Además, Spotify no formaba parte del catálogo
y la interfaz no permitía elegir navegador.

v0.15 agrega una alternativa explícita sin eliminar el aislamiento existente. El
usuario puede conservar el navegador predeterminado, elegir Chrome u Opera GX para
aperturas directas, o habilitar una única pestaña gestionada dentro de su sesión
habitual mediante una extensión local.

## 2. Decisiones

### 2.1 Dos modos visibles

- **Apertura directa:** `open_url` usa el navegador predeterminado o inicia el
  ejecutable fijo de Chrome/Opera GX. YouTube semántico continúa usando Playwright
  aislado.
- **Sesión actual:** sólo está disponible al elegir Chrome u Opera GX. Las URLs de
  catálogo y el flujo semántico de YouTube atraviesan la extensión. Si el puente no
  está conectado, la acción falla; no abre silenciosamente otro navegador.

La preferencia se guarda fuera del repositorio en
`%LOCALAPPDATA%\DesktopAgent\browser_preferences.json`. El esquema es cerrado,
versionado y escrito de forma atómica.

### 2.2 Spotify

`abrí spotify` y `abrí spotify web` abren `https://open.spotify.com/` como destino de
catálogo. `abrí spotify app` y `abrí spotify escritorio` intentan el ejecutable
permitido de la instalación por usuario o de Microsoft Store. El agente no instala
Spotify ni afirma que la aplicación existe cuando Windows no expone el ejecutable.

### 2.3 Reutilización

`YouTubePlaybackTool` conserva un adaptador exitoso y lo reinicia para la siguiente
canción. En Playwright esto reutiliza proceso, contexto y página. En el modo de
extensión se reutiliza una única pestaña cuyo ID conserva la extensión. `detener
youtube` pausa el video y deja la pestaña abierta; cerrar el agente hace la misma
detención segura.

### 2.4 Extensión y host nativo

La extensión Manifest V3 tiene ID estable, permiso `nativeMessaging`, permiso
`scripting`, almacenamiento local y host permission sólo para YouTube. No solicita
historial, cookies, descargas, archivos locales, todas las pestañas ni `<all_urls>`.
Google, GitHub y Spotify sólo se abren como URLs fijas; la extensión no inspecciona
su contenido.

El service worker implementa operaciones semánticas fijas. No recibe scripts,
selectores o URLs arbitrarias y no usa `eval` ni código remoto. Para YouTube sólo
admite abrir, buscar, elegir el primer resultado `/watch`, iniciar, observar y pausar.

Chrome/Opera lanzan `desktop-agent-browser-host.exe` mediante Native Messaging. El
host valida el origen exacto de la extensión y reenvía JSON con frames acotados. Se
conecta al agente por un named pipe de Windows con una clave aleatoria de 256 bits. El
descriptor del pipe se protege con DPAPI para el usuario actual y desaparece al
cerrar. Un lock impide que dos procesos reclamen simultáneamente el mismo puente.

Referencias primarias:

- [Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)
- [Chrome Scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting)
- [Opera Native Messaging](https://help.opera.com/en/extensions/message-passing/)
- [Compatibilidad de extensiones de Opera](https://help.opera.com/en/extensions/)

## 3. Flujo

```text
Orden validada
  -> ActionExecutor
  -> herramienta registrada
  -> preferencia local
       ├── apertura directa -> navegador del sistema o ejecutable fijo
       └── sesión actual -> NativeBrowserBridge
                            -> named pipe autenticado
                            -> host nativo con origen fijado
                            -> extensión Manifest V3
                            -> una pestaña gestionada
```

El modelo sigue sin controlar URLs, ejecutables, permisos, operaciones DOM,
selectores o JavaScript.

## 4. Instalación reversible

El código no instala la extensión automáticamente. Después de instalar el proyecto
en editable para generar el ejecutable del host, el usuario debe ejecutar de forma
consciente:

```powershell
python -m scripts.browser15_bridge_setup --install-host
```

Luego carga `browser_extension` como extensión desempaquetada desde la página de
extensiones de Chrome u Opera GX. La retirada elimina únicamente el manifiesto y la
clave de registro propios:

```powershell
python -m scripts.browser15_bridge_setup --uninstall-host
```

## 5. Validación

Las pruebas automatizadas cubren catálogo y parser de Spotify, persistencia de
preferencias, selección sin fallback oculto, política de perfil, protocolo del pipe,
autenticación lógica, límites, framing de Native Messaging, manifiesto, ID estable,
adaptador semántico, pausa, reutilización y registro reversible con dobles.

`python -m scripts.browser15_qa_check` recorre el nuevo camino sin red, navegador,
registro ni efectos de escritorio. La prueba real requiere instalar el host, cargar
la extensión y confirmar en el navegador elegido apertura de Spotify, reproducción
audible, reutilización de pestaña y pausa sin cierre.

## 6. Límites

- La extensión debe cargarse manualmente en cada navegador que se quiera controlar.
- Sólo una pestaña queda bajo gestión del agente; no adopta pestañas arbitrarias.
- La automatización semántica dentro de páginas sigue limitada a YouTube.
- Spotify web se abre, pero v0.15 no controla búsqueda o reproducción dentro de
  Spotify.
- Si Spotify de escritorio no está instalado o Windows no expone su ejecutable, la
  orden nativa falla de forma explícita.
- Chrome y Opera GX pueden cambiar sus APIs o el DOM de YouTube; los fallos se tratan
  como estado no comprobado.

# Decisión de arquitectura de v0.11

## Alcance

v0.11 centraliza permisos para acciones estructuradas. No registra nuevas herramientas
reales ni habilita operaciones sensibles en la CLI. La interfaz actual sigue usando
acciones `SAFE`; las capacidades no seguras se demuestran con herramientas ficticias.

## Riesgo por efecto

`CapabilityRule` es configuración local y fija capacidad, efecto, intents,
herramientas, argumentos exactos y argumento que representa el destino. El modelo o el
usuario no pueden elegir la clasificación. La taxonomía produce:

- `ALLOW` para observación local, recursos conocidos y control multimedia;
- `CONFIRM` con `CAUTION` para input, modificación y borrado recuperable;
- `CONFIRM` con `DANGEROUS` para envío externo e instalación;
- `BLOCK` para credenciales, seguridad, código arbitrario, borrado irreversible y
  transacciones financieras.

Los efectos bloqueados conservan metadata `DANGEROUS` y nunca generan una solicitud,
por lo que no existe confirmación capaz de habilitarlos.

## Confirmación exacta

El broker calcula fingerprints SHA-256 sobre la acción completa y sobre acción,
capacidad, efecto y destino. La solicitud incluye un request aleatorio, challenge,
fingerprint, destino visible, nombres de argumentos, canales habilitados y vencimiento.
No persiste permisos ni crea aprobaciones generales.

Una decisión válida debe coincidir en todos esos datos. La aprobación emite un token
opaco ligado al fingerprint y al mismo vencimiento. `ActionExecutor` inspecciona el
token y lo consume atómicamente antes del efecto. Si la herramienta falla, el token ya
está consumido y no habilita un reintento silencioso.

## Concurrencia, canales y logs

El estado de requests y grants está protegido por un lock. Dos confirmaciones
simultáneas no emiten dos tokens y dos ejecuciones simultáneas no producen dos efectos.
El canal local se habilita por defecto; el remoto debe declararse en cada solicitud.

Los logs contienen acción, capacidad, efecto, herramienta, estado, canal y duración.
No contienen destino, argumentos, challenge, token o detalles de excepciones. Los
errores inesperados de herramientas se convierten en errores locales redactados.

## Validación realizada

- clasificación independiente de herramientas compartidas;
- metadata, intent, herramienta, argumentos y destino exactos;
- cinco efectos siempre bloqueados sin challenge;
- aprobación local y remota habilitada explícitamente;
- rechazo, cancelación y vencimiento antes o después de aprobar;
- cambio de acción, argumentos o destino y challenge incorrecto;
- consumo de un uso y revocación;
- carreras de aprobación y ejecución con threads;
- fallo de herramienta redactado y autorización consumida;
- 18 pruebas nuevas, 274 totales y QA reproducible sin efectos externos.

## Limitaciones

- no hay todavía una vista gráfica de solicitudes pendientes;
- las reglas no se editan desde configuración ni desde un modelo;
- las capacidades no seguras de QA no son herramientas de producción;
- el estado de requests vive en memoria y desaparece al cerrar el proceso;
- v0.12 conectará política, historial, cancelación y evidencia a la aplicación local.

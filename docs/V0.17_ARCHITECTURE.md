# v0.17 — Uso cotidiano y auditoría

Revisión: 2026-09-11. Implementación local; aceptación personal de voz y extensión
pendiente. No se presenta como asistente universal ni como una release publicada.

## Objetivo y límites

Convertir los recorridos existentes en una aplicación que se pueda dejar configurada,
abrir sin una terminal y usar por texto o una captura de voz explícita. El usuario
autorizó una revisión amplia de problemas reportados; no se agregan control libre,
búsqueda indiscriminada del disco ni acciones sensibles nuevas.

Se mantuvieron el intérprete híbrido, Action, ActionExecutor, registro de herramientas,
catálogo y límite inicial de USD 1/mes. No se agregaron dependencias de producción,
no se ejecutaron llamadas OpenAI reales y no se creó commit/push. El workspace ya
contenía desarrollo no confirmado de v0.15/v0.16; se preservó.

## Defectos encontrados y correcciones

| Problema | Causa comprobada | Corrección y evidencia |
| --- | --- | --- |
| Repetir la API key al abrir | El lanzador anterior sólo conservaba un entorno efímero | GUI con settings persistentes y almacenamiento DPAPI opt-in; roundtrip nativo con clave ficticia |
| Texto libre no reproduce música | El esquema simple de IA sólo proponía apertura de URL/app | PLAY_YOUTUBE y STOP_YOUTUBE, query validada y acciones locales; tests con proveedor falso |
| Silencio pese a `video.muted=false` | El worker no trataba `tab.mutedInfo.muted` | Desmute de pestaña y reproductor, lectura conjunta; tests JS del worker real |
| Cambiar checkbox/navegador no cambiaba reproducción | Se requería Guardar y se reutilizaba el adaptador anterior | Guardado inmediato, clave de sesión y cierre antes del cambio; tests Tk/adaptador |
| Fallo con navegador cerrado | La extensión no puede conectarse sin su navegador | Arranque del navegador seleccionado si falta su proceso y espera de hasta 5 s; nunca fallback a otro perfil |
| Primer resultado aún no disponible | El worker consultaba DOM inmediatamente tras navegación | Espera acotada de resultados/video y solicitudes serializadas; tests JS |
| Pestaña vieja o ajena reutilizada | ID persistido más allá de la sesión sin revisar origen | storage.session y validación de origen antes de reutilizar o inyectar |
| Orden ejecutada después de Detener | Se esperaba al proveedor sin volver a comprobar cancelación | Comprobación antes de ActionExecutor; regresión con proveedor bloqueado |
| Voz enviada después de cancelar o repetida | Un resultado podía quedar esperando en la cola de UI | Correlación de capture_id y consumo único; tests de llegada tardía |
| Fallos de API aparecían como gasto y tiempo cero | Se liquidaban todos los errores como consumo incierto | Rechazos explícitos liberan reserva, errores miden duración; timeouts siguen conservadores |
| Micrófono inesperado | Sólo se usaba el predeterminado, con entradas virtuales presentes | Selector por nombre/API y medidor durante captura; ausencia/ambigüedad falla sin cambiar dispositivo |
| League rechazado al iniciar | Windows negó acceso al lanzamiento directo de LeagueClient | Recorrido del acceso directo instalado: RiotClientServices y argumentos fijos |
| Éxito demasiado amplio en apertura | Un proceso transitorio podía pasar la primera observación | Dos observaciones consecutivas, mensaje explícito de evidencia a nivel de proceso |

## Configuración, privacidad y presupuesto

`app_settings.py` define un esquema estricto y una escritura atómica en
`%LOCALAPPDATA%\DesktopAgent\settings.json`. No modifica el registro de Windows.
Guarda opt-ins, micrófono, tope, modo de envío y atajos. Sólo si el usuario marca
Recordar guarda una clave cifrada para su usuario de Windows. Reutiliza el protector
DPAPI existente; no implementa criptografía propia ni promete protección frente a
programas maliciosos ejecutándose como ese mismo usuario.

El campo de clave no se rellena con el secreto guardado: vacío significa conservarlo.
Quitar clave elimina la copia persistida al guardar y la de la nueva sesión. Si no se
recuerda, una clave sigue disponible durante el reinicio interno de configuración,
pero no al cerrar completamente el proceso. Los errores y repr no incluyen secretos.

Las opciones guardadas prevalecen sobre las del entorno para la GUI. Sin archivo se
usan los opt-ins iniciales del entorno; la CLI conserva su configuración de entorno.
Settings dañados fallan sin activar IA. La configuración sólo se cambia con la cola
inactiva y sin captura en curso; se reinicia el servicio para evitar mezclar claves o
presupuestos. Se conservan preferencias y consumo; historial temporal y reproducción
no se conservan durante ese reinicio.

El libro compartido sigue en `ai_usage.json`. Rechazos de voz conocidos liberan la
reserva; timeout/red o respuesta incierta conservan el costo estimado. No se corrigen
automáticamente cargos estimados de pruebas históricas, ni se presenta el contador
como saldo o factura del proveedor. Los tokens de audio no se inventan.

## Captura y atajos

La captura usa WAV mono de 16 bits en memoria, hasta 20 s; espera hasta 5 s de silencio
inicial y termina después de 1,2 s de silencio final. El botón Terminé de hablar o
una segunda pulsación del atajo finalizan sin descartar. Cancelar descarta el resultado;
una solicitud externa que ya se envió puede consumir aunque no ejecute nada.

La clave estable del micrófono combina API de audio y nombre. Se vuelve a resolver
antes de capturar para tolerar cambios de índice al conectar USB. Si desaparece o el
nombre es ambiguo no se elige otro dispositivo. El medidor no graba en segundo plano.
El detector RMS no es un modelo avanzado de detección de voz y puede confundirse con
ruido o audio de altavoces; la calidad de transcripción depende del servicio externo.

`gpt-transcribe` continúa sin prompt, palabras clave ni frases privilegiadas. La
interpretación y la transcripción son etapas distintas. Envío automático está apagado
por defecto y no significa comprensión universal: una mala transcripción puede elegir
una acción permitida incorrecta; se recomienda validar primero en modo revisión.

`hotkeys.py` registra Ctrl+Alt+Espacio y Ctrl+Alt+Esc mediante RegisterHotKey y
MOD_NOREPEAT. Un hilo recibe exclusivamente WM_HOTKEY y la UI consume eventos; no hay
hook de teclado, palabra de activación ni escucha permanente. Se liberan los registros
al cerrar y se revierte un registro parcial si la otra combinación está ocupada.

## Navegador y aplicaciones

Las rutas y argumentos para arrancar navegadores son de catálogo. Si Chrome/Opera ya
está abierto sin extensión, el agente no abre otra ventana cada vez; espera hasta
5 s y ofrece diagnóstico. Sólo un navegador puede estar conectado al puente a la vez.
La extensión sigue con permiso de contenido limitado a YouTube; no se solicitan
permisos nuevos ni se automatiza su instalación/activación.

El worker v0.17 mantiene una pestaña gestionada por sesión, preserva la URL de YouTube
al iniciar otro recorrido y no toma control de una pestaña que el usuario llevó a un
origen ajeno. Cambiar de preferencia cierra el adaptador anterior antes de crear otro.
Detener pausa pero no cierra la pestaña habitual. Las esperas internas se acotan por
debajo del timeout del puente; la verificación sigue exigiendo avance de tiempo y
reproducción no silenciada. No puede confirmar el volumen físico de Windows/parlantes.

La prueba real de arranque conectó la extensión, pero la apertura del sitio falló en
unos 2,4 s y Chrome mostraba su selector de perfiles. Esto apunta al caso documentado
de un worker sin ventana actual; no se obtuvo el detalle interno de ese error. Se añadió
la creación explícita de una ventana normal dentro del perfil de la extensión cuando
no existe ninguna, sin seleccionar otro perfil ni cambiar la configuración de Chrome.
Ese caso tiene una regresión JS; requiere recargar la extensión para la aceptación real.

El acceso directo instalado de League especifica:

```text
RiotClientServices.exe --launch-product=league_of_legends --launch-patchline=live
```

El código usa esos argumentos fijos de catálogo, no ejecuta el contenido arbitrario
de un acceso directo ni texto de un modelo. El directorio de inicio es el del
ejecutable. Se reprodujo el rechazo de Windows al ejecutable directo y se comprobó
que la ruta corregida deja Riot Client activo; no se comprobó League listo. Login,
actualización y restricciones del juego requieren intervención manual. Nunca se
elevan privilegios para sortear un rechazo.

## Validaciones

La base de 401 tests ya aprobaba al empezar. Eso no garantizaba los recorridos reales:
se añadieron regresiones, sin borrar ni debilitar las comprobaciones de seguridad.
Los asserts actualizados reflejan nuevos intents, mensajes más precisos, versión y
la decisión explícita de no contabilizar rechazos como transcripciones consumidas.

Comandos reproducibles desde el repositorio:

```powershell
python -m unittest discover -s tests -v
node --test tests/browser_extension.test.cjs
python -m scripts.polish17_qa_check
python -m scripts.vis08_simulated_check
python -m scripts.loop08_qa_check
python -m scripts.recipe10_qa_check
python -m scripts.policy11_qa_check
python -m scripts.ui12_smoke_check
python -m scripts.voice13_qa_check
python -m scripts.remote14_qa_check
python -m scripts.browser15_qa_check
python -m scripts.application16_qa_check
```

Se ejecutaron los runners históricos anteriores con éxito. Los tests de JS ejecutan
el worker real contra Chrome/DOM ficticios, sin red. Los tests Tk usan Tcl/Tk real
con servicios y transcripción ficticios; DPAPI se prueba con una clave sintética.
En el entorno de Codex, Node y Tcl/Tk necesitaron ejecución fuera del sandbox: el
primer intento restringido falló por acceso a rutas del runtime, no por el producto.
`git diff --check` no informó errores de whitespace; no se incorporó un linter nuevo.

Resultado de la suite final: **439 tests Python y 9 tests JS aprobados**. El runner de aceptación
v0.17 ejecutó **119 tests** de esa suite. El registro/liberación de ambos atajos también
se comprobó contra Windows real, sin capturar voz ni ejecutar órdenes.

Comprobaciones adicionales: GUI abierta e inspeccionada con Computer Use, envío
de “Abrí calculadora.” desde la ventana y evidencia de proceso; consulta local de
dispositivos de entrada (HyperX y FaceCam entre varias entradas VoiceMeeter); host
nativo instalado válido; diagnóstico y arranque de Riot Client. La medición inicial
de 41 ms correspondía al chequeo de proceso previo, no a tiempo garantizado de ventana
lista ni a la latencia completa desde una conversación con Codex.

No se grabó audio real, no se usó una API key ni se hizo una llamada OpenAI real en
esta auditoría. Tampoco se repitió la automatización nativa histórica de mouse/teclado
(fuera del recorrido modificado) ni se desplegó el relay remoto.

## Checkpoint personal antes del siguiente desarrollo

1. Abrir v0.17, configurar clave/opt-ins y Recordar si corresponde. Elegir el
   micrófono HyperX físico y comprobar que el medidor responde al hablar.
2. Dictar tres frases distintas en modo revisión, corregir si hace falta y enviar.
   Comprobar que cancelar no las ejecuta y que el contador refleja las solicitudes.
3. Activar atajos y, opcionalmente, envío automático. Probar desde otra aplicación.
   Comprobar Ctrl+Alt+Esc y el cierre/liberación del atajo.
4. Recargar la extensión instalada y comprobar conexión. Reproducir dos canciones
   seguidas, comprobar audio, misma pestaña y pausa sin cerrar la pestaña.
5. Probar las aplicaciones habituales. En League, resolver manualmente cualquier
   requisito de Riot y repetir la orden; no considerar sólo Riot abierto como juego listo.

Próximo paso recomendado: cerrar ese checkpoint, luego acordar una sola capacidad
adicional, como proyectos/documentos explícitamente seleccionados por el usuario.
Siguen pendientes Spotify por playlist, volumen por dispositivo, respuesta hablada,
control móvil desplegado, uso de apps desconocidas y control autónomo general.

Commit sugerido (no ejecutado): `feat: polish daily voice workflows and browser reliability`.

### Mantenimiento posterior (2026-09-14)

La pausa explícita ahora consulta la pestaña de YouTube gestionada aunque el
controlador ya no conserve un adaptador en memoria, por ejemplo si el usuario
reanuda el video manualmente. No abre un navegador desconectado ni toma pestañas
ajenas. Una página gestionada sin reproductor se considera ya detenida, evitando que
una búsqueda fallida bloquee la siguiente orden. Buscar otro contenido, pausar el
actual y reanudarlo son acciones diferenciadas; la
reanudación verifica que el mismo video vuelva a avanzar y no convierte el pedido en
una consulta. Resultado automatizado vigente: **489 tests Python y 13 tests JS
aprobados**. El usuario aceptó reproducción, pausa y reanudación reales de YouTube el
2026-09-25; `POLISH-08` mantiene pendientes voz, cancelación y atajos.

## Fuentes y autoría

El diseño, la implementación y las pruebas fueron asistidos por IA. El usuario
conserva decisiones y aceptación. Transcripción/interpretación son servicios externos;
DPAPI, RegisterHotKey, PortAudio y APIs de Chrome son capacidades de sus proveedores.
Se usó la guía de OpenAI para verificar el contrato de salida estructurada y el modelo,
y Computer Use para inspeccionar la UI; no se atribuyen esas capacidades al proyecto.

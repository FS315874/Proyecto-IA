# Decisión de arquitectura de v0.8

## Alcance

v0.8 entrega un clic o texto a un elemento de una observación vigente. No permite un
stream libre de mouse/teclado, atajos arbitrarios, terminales, autenticación ni campos
secretos. La CLI y la GUI todavía no exponen esta capacidad.

## Contrato de autorización

`InputAction` declara `RiskLevel.CAUTION` y `requires_confirmation=True`. Identifica
acción, ventana, revisión, observación y elemento mediante valores locales saneados.
La escritura además contiene texto acotado; el clic puede habilitar explícitamente un
fallback de coordenadas.

`InputController.prepare` valida el contexto y crea un challenge aleatorio ligado a la
acción, con treinta segundos de vigencia. `execute` consume el challenge una sola vez
y exige una decisión aprobatoria coincidente. El presupuesto predeterminado es de
cinco acciones y se comprueba al preparar y al ejecutar.

## Estado y foco

El backend informa existencia, visibilidad, minimización, foreground, proceso, tamaño,
modal, contexto bloqueado y control enfocado. El controlador valida antes del foco,
después del foco, después de resolver el control y después del input. Una pérdida de
foco, resize, proceso distinto, modal o contexto bloqueado detiene el flujo.

Todo intento que pudo modificar el foco invalida la observación y su revisión, incluso
si no entregó el input. Una acción exitosa también invalida inmediatamente el estado
anterior. Por eso ningún segundo clic puede reutilizar la misma caja.

## Accesibilidad y fallback

Los controles Win32 se enumeran como hijos de la ventana exacta, se clasifican por rol
y se emparejan con la caja visual mediante IoU. Botones, checkbox y radio se activan
con mensajes dirigidos. Un Edit recibe foco verificado, luego texto directo y una
comparación final; los valores nunca se registran.

Si no existe control accesible, solo un clic puede usar fallback y únicamente al centro
de la caja de un `VisualElement` registrado. No existe una API pública para que el
modelo elija un punto libre. La escritura nunca usa coordenadas.

## Bloqueos y emergencia

El backend falla cerrado cuando no puede identificar el proceso. Bloquea terminales,
PowerShell, registro, credenciales, UAC, seguridad, gestores de contraseña y títulos
asociados a login. Los controles password se rechazan.

`InputController` requiere un `EmergencyStop`; no crea un token inalcanzable por
defecto. `WindowsEmergencyHotkey` registra `Ctrl+Alt+Esc` en un hilo dedicado y activa
ese canal. La cancelación se comprueba antes de resolver y antes de entregar input.

## Validación realizada

- confirmación aprobada, rechazada, incorrecta, caducada y reutilizada;
- presupuesto revalidado con acciones ya preparadas;
- clic accesible y fallback explícito al centro del elemento;
- escritura con foco y verificación sin contenido en logs;
- bloqueo de password y caracteres de control;
- pérdida de foco, proceso distinto, modal y contexto bloqueado;
- emergencia durante resolución sin entrega de input;
- errores de backend redactados e invalidación conservadora;
- catorce pruebas con dobles y suite completa de 220 pruebas;
- demo Win32 real sobre ventana propia con datos ficticios;
- escritura y clic accesibles verificados con `Ctrl+Alt+Esc` registrado.

## Limitaciones

- el adaptador real cubre controles Win32 clásicos, no toda la superficie UIA moderna;
- el clic confirma entrega y continuidad de estado, pero un efecto arbitrario necesita
  una observación posterior para verificarse semánticamente;
- el hotkey cancela en límites seguros, no interrumpe una llamada Win32 ya bloqueada;
- no hay integración cotidiana en CLI/GUI hasta versiones posteriores.
